SparkLang · v0.6.62 · Changelog

Write it. Compile it. Prove it.

SparkLang is an open language for AI work. Programs compile to a bytecode you can dump and inspect line by line. Training, serving, and real voice — ears and speech — are built in. It runs offline and self-hosted, with no API keys required.

Every capability on this site ships with a command you can rerun yourself. MIT licensed. Source on GitHub.

Why a language?

One file, not a sprawl of scripts

AI work tends to sprawl: a prompt in one repo, a training script in another, an eval harness in CI. A Spark program puts the whole job in one file you can read top to bottom — and rerun exactly, on your machine, with no accounts.

The usual sprawl

client = OpenAI(...)
resp = client.chat.completions.create(...)
# separate train script, eval notebook,
# CI secrets, ad-hoc shell glue…

One Spark program

model train dataset "examples/fixtures/train/dataset.jsonl" base "fixture-base" out "out/train/job-dry-001" backend "http" -> job
model status "job-dry-001" -> status
expect contains job fixture "examples/fixtures/train/want_accepted.txt"
expect contains status fixture "examples/fixtures/train/want_succeeded.txt"

# ./spark --dry-run examples/train_eval.spark

Capabilities

What Spark does for you

Three things a single Spark file gives you that scattered scripts do not.

Offline by default

Every example runs with no network and no keys — nothing leaves your machine. Go live only when you point Spark at your own services. 

./spark --dry-run examples/model_train.spark

Real training, on your hardware

Submit a training job from the same file, poll its status, and bind the artifacts. Spark ships five reference trainers that run on CPU — distillation, preference packing, playbook fitting, FAQ indexing, and reply packing — so the full loop works on a laptop. When you outgrow them, point Spark at your own training service over HTTP. Proof: live-train-capture.txt, live-train-methods-capture.txt. 

model train dataset "examples/fixtures/train/dataset.jsonl" base "fixture-base" out "out/train/job-dry-001" backend "http" -> job
model status "job-dry-001" -> status

Pass/fail in the same file

After a run, assert on the actual output. Expectations exit 0 or 1 — the gate judges this run, on this machine, and you can rerun it. 

expect contains job fixture "examples/fixtures/train/want_accepted.txt"
expect contains status fixture "examples/fixtures/train/want_succeeded.txt"

The training loop

Train → status → expect

The whole training loop is three lines: submit a job, poll its status, assert the result. It runs offline out of the box. When you are ready for real training, point Spark at your training service — the same file goes live.

  1. 1 Train Submit dataset, base, and output path
  2. 2 Status Poll the job and bind artifact JSON
  3. 3 Expect assert bound job/status (exit 0/1) 
# examples/train_eval.spark — dry-run first
model train dataset "examples/fixtures/train/dataset.jsonl" base "fixture-base" out "out/train/job-dry-001" backend "http" -> job
model status "job-dry-001" -> status
expect contains job fixture "examples/fixtures/train/want_accepted.txt"
expect contains status fixture "examples/fixtures/train/want_succeeded.txt"

Fail path: examples/train_eval_fail.spark exits 1. Live proof against the reference trainers: live-train-methods-capture.txt. Model training docs · Build a Model · What's shipping today.
